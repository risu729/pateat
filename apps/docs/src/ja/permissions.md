# 権限

Pateat が Chrome に求める権限は、役割に必要な最小限です。このページでは、マニフェストにある権限ごとに、Pateat がそれを何に使うかを説明します。

| 権限 | Pateat が使う目的 |
| --- | --- |
| すべてのサイトへのアクセス（`https://*/*` と `http://*/*`） | ログインページを見つけて完了させる、パスキー要求に応答する、Bitwarden サーバー、Pateat サービス、自分のキーがあれば Anthropic の API に接続する |
| `storage` | 設定、レシピの写し、保管庫の接続情報、サービスとのペアリング、Anthropic API キーを Chrome 内に保存する |
| `offscreen` | 非表示の拡張機能ページで Bitwarden SDK を動かし、そこで保管庫を復号し、パスキー要求に署名する |
| `alarms` | サービスワーカーが休止していても 5 分ごとに保管庫を同期し直す時期かを確かめる、タイムアウトが来たら保管庫をロック（またはログアウト）する |
| `idle` | その[保管庫のタイムアウト](./setup.md#vault-timeout)を選んだとき、コンピューターがアイドルになるかロックされたら保管庫をロック（またはログアウト）する。この権限に Chrome は警告を表示しません |

Pateat は `tabs`、`scripting`、`activeTab`、`cookies`、`webRequest`、`history`、`nativeMessaging` など、ほかの権限は求めません。

## すべてのサイトへのアクセス {#access-to-all-sites}

Pateat は、サイトごとにあとで求めるのではなく、インストール時にすべての HTTPS と HTTP のサイトへのアクセスを宣言します（[ADR 0009](https://github.com/risu729/pateat/blob/main/docs/adr/0009-install-time-https-site-access.md)、[ADR 0050](https://github.com/risu729/pateat/blob/main/docs/adr/0050-http-pages-for-http-items.md)、英語）。そのため、サイトを増やしても Chrome の確認は出ません。その代わり、Chrome は Pateat がすべてのウェブサイト上のデータを読み取り、変更できると警告し、Pateat のスクリプトはすべての HTTP と HTTPS のページで読み込まれます。

- ログイン用のスクリプトが、すべてのページとフレームで動きます。ページがログインの対象として認められるまでは、ページがあることを Pateat のサービスワーカーに知らせるだけです。その横で、ページ自身のコンテキストでもう 1 つの小さなスクリプトが動きます。これはページから何も読まず、ログイン用のスクリプトに頼まれたときだけ `javascript:` のリンクを開き、そのリンクがページ自身のセキュリティポリシーの下で動くようにします。
- 2 つのパスキー用のスクリプトが、HTTPS のすべてのトップレベルのページと、ブラウザーがパスキーを認める `http://localhost` のすべてのページの始めに動きます。1 つはページのパスキー要求（`navigator.credentials.get` と `create`）を包み、もう 1 つは要求を Pateat のサービスワーカーに中継します。Pateat が応答しない要求はそのまま Chrome に渡るので、Chrome、スマートフォン、ほかのパスキープロバイダーが応答できます。例外は 3 つです。Pateat のアカウント選択が選ばれずに時間切れになった要求は、Chrome 自身の確認が時間切れになったときと同じように失敗します。Pateat がサインインさせたあとにページが求めたパスキーの候補表示は、ページが取り消すまで待ちます。Pateat がタブをサインインさせた直後に、保管庫のパスキーを含むパスキーの作成を求められたときは断ります。

ページで読み込まれることは、そのページで何かをすることではありません。Pateat がログインするのは、除外しておらず、保管庫のアイテムに一致するかアイテムを選んだサイトで、そのページのレシピがあり、Chrome でサイトへのアクセスがまだ許されているときだけです。保管庫のロックも解除されている必要があります。入力するのは、そのオリジン専用のレシピが指定したフィールドだけで、そのタブ、フレーム、ページの中だけです。レシピのないページは、レシピを書くために Pateat サービスへ記述を送ることがあります。記述に何が含まれるかは[プライバシーポリシー](./privacy.md)にあります。

ツールバーのアイコンに、今のタブに一致する保管庫のアイテムの数を出すため、Pateat はタブのアドレスを端末上で保管庫と照らし合わせます。これにはレシピは要らず、何も送らず、除外したサイトでも行います。

同じアクセスで、Pateat は Bitwarden サーバー、Pateat サービス、[AI キー](./setup.md#ai-key)を保存したときは Anthropic の API（`https://api.anthropic.com/v1/messages`）に接続します。どこでも、必要な決まったエンドポイントだけを呼びます。Bitwarden では、選んだサーバーのものだけです。

## 暗号化されていない HTTP のページ {#plain-http-pages}

HTTP のページでは、保管庫で `http://192.168.1.1` のように `http://` を明示したアドレスで保存したアイテムだけでログインします。`https://example.com` や、`example.com` のようにスキームなしで保存したアイテムは、同じサイトでも使いません。これは Bitwarden より厳しい扱いです。Bitwarden は警告のうえでそうしたアイテムも入力しますが、自動ログインでは警告に答える人がいないためです。HTTP のページでのログインも HTTPS と同じように入力して送信しますが、`http://localhost` 以外ではパスキー要求に応答しません。

HTTP では、パスワードを含め Pateat が入力したものは暗号化されずに送られます。あなたとサイトの間のネットワークにいる人なら誰でもそれを読み取れ、ページを書き換えて、差し込んだフォームに Pateat が入力するようにもできます。`http://` でアイテムを保存するのは、ルーターのように、そのネットワーク上で信頼できるサイトだけにしてください。

## サイトへのアクセスを制限する {#limiting-site-access}

Chrome では、どの拡張機能にもサイトへのアクセスを許さないようにできます。`chrome://extensions` の Pateat のカードで **詳細**、**サイトへのアクセス** を選びます。Pateat はサイトごとにその選択に従います。アクセスがないサイトではログインもパスキー要求への応答もせず、Bitwarden サーバーや Pateat サービスに接続する必要があるときは、設定ページがアクセスを求めます。

ほかのサイトへのアクセスは残したまま 1 つのサイトで Pateat を止めるには、ツールバーのポップアップで **このサイトで Pateat を使う** をオフにします。同じ設定プロファイルを使うすべてのデバイスが従う除外が追加されます。

## ストレージ {#storage}

Pateat はデータを Chrome 内の拡張機能自身のストレージ（`chrome.storage` と IndexedDB）に保存します。ウェブサイトからは読めません。Chrome から拡張機能を削除すると、すべて消えます。保管庫のタイムアウトが **なし** でなければ、ロックを解除した保管庫の鍵はメモリー（`chrome.storage.session`）にだけ置かれ、Chrome の再起動や拡張機能の再読み込み、更新で消えます。
