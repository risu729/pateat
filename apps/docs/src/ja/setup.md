# 初期設定

Pateat の初期設定は、設定ページでの 2 つの手順です。Bitwarden 保管庫に接続し、拡張機能を Pateat サービスとペアリングします。設定ページは、ツールバーのポップアップの **設定を開く** ボタン（スライダーのアイコン）か、`chrome://extensions` の Pateat のカードの **詳細**、**拡張機能のオプション** から開きます。

Pateat の画面は Chrome の言語（英語か日本語）に合わせて表示され、設定ページの **言語** で選ぶこともできます。このページは日本語の表示名で書いています。

## Bitwarden に接続する {#connect-bitwarden}

1. **接続を追加** で **サーバー** を選びます。**Bitwarden クラウド（米国）**、**Bitwarden クラウド（EU）**、または **セルフホスト** です。セルフホストは、自分の Bitwarden サーバーと最新版の Vaultwarden を含みます。セルフホストでは、`https://vault.example.com` のように **サーバーのアドレス** を入力します。HTTPS が必要で、`localhost` と `127.0.0.1` だけは例外です。
2. 接続に `Personal` のような **名前** を付け、Bitwarden の **メールアドレス** と **マスターパスワード** を入力します。
3. **この保管庫を使う** をオンのままにして、**Bitwarden に接続** を押します。
4. Bitwarden が確認を求めると、**手動での確認** のフォームが出ます。**確認方法** を選びます。認証アプリに表示されるコードなら **認証アプリのコード**、サーバーからメールで送ってもらうなら **メールのコード** を選びます（**コードを再送信** でもう一度送ってもらえます）。新しいデバイスでは、Bitwarden が新しいデバイスの確認コードを自動でメールします。設定ページを閉じずに 5 分以内にコードを入力し、**コードを確認** を押します。ほかの 2 段階認証の方式にはまだ対応していません。

Pateat はブラウザーから直接 Bitwarden サーバーにログインし、保管庫を同期して、公式の Bitwarden SDK でこの端末上で復号します。マスターパスワードと確認コードは保存しません。この端末に残るのは次のものです。

- 暗号化された保管庫の写し
- ロック解除の鍵。保管庫のロックを解除している間、その写しを復号します。
- 同期用のログイン情報。あとで保管庫をもう一度同期するのに使います。

接続はそれぞれ 1 行で表示され、主な操作のボタンがあります。ふだんは **同期**、保管庫がロックされているときは **ロック解除**、先にログインが必要なときは **再ログイン** です。**ロック解除** はマスターパスワードを求め、サーバーを使わずにこの端末で確かめます。行のメニューには、ロック解除の鍵を消して同期用のログイン情報を残す **ロック**、両方を消す **ログアウト**、**同期用のログイン情報を削除**、**接続を削除** もあります。**接続を削除** は、もう一度 **接続を削除** を押して確定すると、接続、保管庫の写し、ロック解除の鍵、同期用のログイン情報をこの端末から消します。どれも、ほかの Bitwarden のセッションからはログアウトしません。個人用と仕事用のように、接続はいくつでも追加できます。

### Pateat に使わせるものを選ぶ {#choose-what-pateat-may-use}

接続の行では、Pateat が使えるアイテムも決めます。

- **この保管庫を使う** で、その接続を Pateat に使わせるかどうかを切り替えます。
- **Pateat が使うアイテム** は、**除外設定以外のすべて** か **選択したグループとアイテムのみ** です。
- **除外するアイテムとフィールド** には、Pateat に決して入力させないアイテムと、アイテムのフィールドを並べます。除外は、選択したグループとアイテムより優先します。

除外したカスタムフィールドのあるアイテムが変わり、どのフィールドを除外したのか Pateat が判断できなくなると、このページでフィールドを確認するまで、そのアイテムを使いません。

ツールバーのポップアップにも、確認を待つアイテムを表示します。**設定でフィールドを確認** を押すと、このページが開きます。ポップアップを開くだけでは、確認の承認や除外設定の変更は行いません。

保存したカスタムフィールド名が見つからないか、区別できなくなってログインが止まったときは、ポップアップの **保管庫のフィールドを確認** で、各入力欄に使う現在のフィールドを選び、**このフィールドで再試行** を押します。候補には、使うことが許可されたカスタムフィールドの名前だけを表示します。そのページでログインを再試行し、成功を確認してから修正を保存します。マスターパスワードの入力が必要なアイテムでは、Pateat が開くウィンドウで入力すると、選んだフィールドでログインを再試行します。ページ、保管庫、設定、プロファイルが変わった場合は、ページを再読み込みして確認し直してください。組み込みフィールドの不足や、レシピの入力欄の変更は、この操作では修正しません。

これらの制限は Pateat にだけ効き、Bitwarden 側は何も変わりません。

## Pateat サービスとペアリングする {#pair-with-a-pateat-service}

1. **同期サービス** で、`https://pateat.example.com` のような **サービスのアドレス** と、サービスのデバイス一覧に表示される **デバイス名** を入力します。
2. **このデバイスをペアリング** を押します。
3. まだサービスにログインしていなければ、Pateat が新しいタブでサービスのログインページを開きます。そこでログインして設定ページに戻ると、Pateat が自動でやり直します。**再試行** と **ログインページを開く** で、それぞれの手順を繰り返せます。
4. サービスにすでに設定があれば、**設定プロファイル** を選びます。既存のプロファイルか、**このデバイスのサイト設定で新しいプロファイルを作成** を選んで **新しいプロファイルの名前** を入力します。プロファイルは、再開するまで一時停止したサイト、許可サイト、マスターパスワードを求めるサイト、既定のアカウント、ページでの動作、プライベートウィンドウで自動ログインするかどうかを持ち、同じプロファイルのデバイスはそれを共有します。既存のプロファイルを選ぶと、このデバイスのリストはプロファイルのものに置き換わります。このデバイスに一時停止したサイト、許可サイト、マスターパスワードを求めるサイト、既定のアカウントのどれかがあるか、**許可サイトでだけ自動ログインする** がオンのとき、またはページでの動作の既定値やサイトのルールを変更しているときは、先に確認します（**置き換えてペアリング**）。

ペアリングに成功すると、**このデバイスをペアリングしました。** と表示されます。その後、Pateat はプロファイルの設定とレシピをサービスから同期し、この端末に写しを持ちます。

サービスはこのデバイスに専用の認証情報を発行します。拡張機能はそれを自身のストレージに保存し、サービスにだけ送ります。90 日使われないと期限が切れます。コンピューターをなくしたときなどは、設定ページの **このデバイスの接続を解除** を押すか、サービスの **Devices** ページで取り消せます。なくしたコンピューターを取り消すと、サービスには接続できなくなりますが、そこにすでにある保管庫の写し、ロック解除の鍵、レシピは消せません。

### Pateat サービス {#the-pateat-service}

サービスは小さな Cloudflare Worker です。ペアリングと管理のページは Cloudflare Access で保護され、拡張機能はデバイスの認証情報で接続します。サービスは、設定プロファイル、どの保管庫のフィールドが各サイトのログインのどこに入るか、レシピを保存し、レシピのないログインページには Claude でレシピを書きます。また、受け取ったページの記述、レシピに従ったログインごとの記録、拡張機能が報告した問題を 1 年間保存します。詳しくは[プライバシーポリシー](./privacy.md#your-pateat-service)にあります。保管庫の値や鍵は受け取りません。サービスのページは **Dashboard**、**Sites**、**Profiles**、**Devices**、**Claude**（Claude の認証情報と使うモデル）、**Problems**（デバイスが報告した警告、エラー、何もしなかった理由）、**Request log** です。**Request log** の **Login history** には、サービスが保存しているログインの記録を表示します。**Site** に `https://example.com` のようにサイトのアドレスを入力し（パスは無視します）、**Result** で結果を選んで **Apply filters** を押すと絞り込めます。一覧の上の件数に、適用中の絞り込みも表示します。**Older** で古い記録に進み、**Newest** で最新の記録に戻れます。各記録の **Details** にはレシピ、結果のコード、記録した所要時間があり、ネットワークの時間はサービス待ち時間の一部です。**Delete all** は、保存された依頼のログ、ログインの記録、問題の報告をすべて削除します。サービスのページはまだ英語だけです。

今のところ、サービスはそれぞれ持ち主が自分のために運用しています。`pateat.takuk.me` のサービスは Pateat の開発者のもので、ほかの人は使えません。サービスは運用者が登録した拡張機能 ID からのペアリングだけを受け付けるので、自分で運用するには Pateat の ID か、自分の鍵で署名した自分のビルドの ID を登録します。どちらも[開発ガイド](https://github.com/risu729/pateat/blob/main/docs/development.md#extension-id)（英語）にあります。ペアリングしていない端末でレシピを書けるようにする予定です。

## その他の設定 {#more-settings}

### 保管庫のタイムアウト {#vault-timeout}

**保管庫のタイムアウト** で、保管庫のロックを解除しておく時間を決めます。最後にログイン情報を入力した、パスキーで署名した、ロックを解除した、ログインした時点から数えます。1、5、15、30 分、1、4 時間、**システムのアイドル時**、**システムのロック時**、**ブラウザの再起動時**、**なし**（既定）、**カスタム** の分数から選びます。**タイムアウト時の動作** は **ロック** か **ログアウト** です。この設定はほかの設定と一緒に同期し、すべての端末に適用されます。時間は端末ごとに数えます。

**なし** では、ロック解除の鍵を Chrome 内の拡張機能のストレージに保存するので、Chrome を再起動しても保管庫は自動でロック解除されます。この鍵は OS のキーストアで保護されていないので、この Chrome のプロファイルを使える人や、そのファイルを読める人は保管庫を使えます。ほかのタイムアウトでは鍵はメモリーにだけあるので、Chrome の再起動や、拡張機能の再読み込みや更新でも保管庫はロックされます。

### マスターパスワードを求めるサイト {#sites-that-ask-for-the-master-password}

Bitwarden のマスターパスワードの再要求は、指定したサイトで守ります。ツールバーのポップアップでそのサイトの **マスターパスワードを求める** をオンにするか、設定ページの **サイト** で **マスターパスワードを求める** から追加します。**サブドメインを含める** でサブドメインも対象になり、**求めない** で外せます。それらのサイトでは、再要求が設定されたログインアイテムとそのパスキーは、Pateat の画面でマスターパスワードを入力してから使います。ほかのサイトでは、ふつうのアイテムと同じように使います。再要求を確かめるのはログインアイテムだけで、リンクしたカードや ID のアイテムの値は、そのアイテムに再要求が設定されていても尋ねずに入力します。最初は何も登録されていません。

### 許可サイト {#allowed-sites}

Pateat が自分でログインするサイトを一部に絞るには、設定ページの **許可サイト** で **許可サイトでだけ自動ログインする** をオンにし、**サイトを許可** でサイトを 1 つずつ追加します。**サブドメインも許可する** を選ぶと、そのサブドメインも含みます。オンのあいだ、ほかのサイトは「再開するまで」一時停止したのと同じ扱いになります。Pateat はそこで自分からログイン、入力、ページの送信をしませんが、ツールバーのポップアップでアカウントを選べばログインします。一時停止したサイトは、許可しても一時停止のままです。オンにしてどのサイトも許可していないと、どのサイトでも自動ログインは一時停止します。オフにしてもリストは残ります。許可サイトでないサイトでは、ツールバーのポップアップに **（サイト名）を許可** が出て、押すとそのサイトをサブドメインごと許可します。リストは最初は空でオフになっており、一時停止したサイトと同じく設定プロファイルに属します。

### ページでの動作 {#page-behavior}

**ページでの動作** の **プロファイルの既定値** で、**ログインページ** を **自動** か **入力のみ** にします。サイトのルールがなければ、プロファイルの既定値を使います。**サイトごとのルール** で **サイト** を入力し、必要なら **サブドメインにも適用する** を選んで **サイトのルールを追加** を押します。ページの種類ごとに、最も具体的なホスト名のルールが優先します。設定はプロファイルと同期し、エクスポートとインポートにも含まれます。ツールバーのポップアップでは今のホストだけを変更します。サブドメインも対象のルールは、範囲を確かめられる設定ページで編集します。

**入力のみ** では Pateat が入力し、ボタンの操作、認証コードの入力、ソフトウェアキーボードの操作は自分で行います。既定のアカウントか、一致する唯一のアカウントで通常のログイン欄を入力します。**次へ** や **ログイン** は自分で押してください。次のページのレシピがあれば入力し、なければ続きのレシピを依頼します。自分で編集した欄を上書きせず、ボタンを押したり、ソフトウェアキーボードを操作したり、認証コードを入力したりしません。入力だけでページが進む・送信されるとレシピに記録された欄も空のままにします。複数のアカウントが一致するときはポップアップで選びます。この明示的な選択では、ボタンを押す通常のログインを開始します。パスキーしかないアイテムには、入力するパスワードの欄がありません。自動で出るパスキー要求はブラウザーに任せ、自分で開始した要求には通常のパスキーの確認ルールを適用します。

一時停止、許可サイト、プライベートウィンドウの設定、保管庫の制限は引き続き適用されます。

**ログイン後の本人確認** の **入力のみ** では、このタブとブラウザーのセッションで Pateat のログイン成功を確認したアカウントだけを使います。別のアカウントを選ぶことはありません。**ログインページ** の **入力のみ** で、ボタンを自分で押したログインでは使いません。**オフ** では何もしません。入力するのは、まだ編集されていない空の通常の入力欄だけです。ボタンの操作、認証コードの入力、ソフトウェアキーボードの操作、入力だけでページが進む・送信される欄は自分で行います。内容を確認して、ボタンは自分で押してください。パスキーによる本人確認は、どちらの設定でもブラウザーに任せます。マスターパスワードを求めるアイテムでは、本人確認ページごとにもう一度求め、入力するとそのページに入力します。別のアカウントのマスターパスワードのウィンドウがすでに開いているときは、それが閉じた後にこのアカウントについて求めます。ウィンドウを閉じた場合、そのページには入力しません。

自分でログインした後など、Pateat がログインしていない本人確認ページでは、**ログイン後の本人確認** が **入力のみ** のとき、ポップアップに **今すぐログイン** の代わりに **入力** を表示します。ページに一致するアカウントを選んで **入力** を押すと、そのアカウントのパスワード（ページが秘密の質問の答えを求めるときはその答え）を 1 回だけ入力し、ボタンは押しません。一時停止中のサイトやプライベートウィンドウでも使え、マスターパスワードを求めるアイテムではマスターパスワードを求めます。埋め込みフォームには、周りのページにも一致するアカウントだけを入力します。自分で入力した値はそのままにし、Pateat が前に入力した値は、ページのスクリプトが編集の操作なしに変えた場合も含め、今回選んだアカウントの値に置き換えることがあります。レシピがあるページを AI にもう一度判定させることはありません。レシピがまだない、秘密の質問の答えを求めるページは、レシピを作るために記述を 1 回送り（通常の上限と料金が適用されます）、本人確認ページと判定された場合だけ入力します。それ以外の判定の場合は、そのページは自分で操作してください。判定の結果が得られなかった場合（上限や利用不可など）は、理由が表示され、もう一度 **入力** を押すと再度送ります。**入力** はアカウントを記憶せず、設定も変更しません。もう一度入力するには、もう一度押してください。

新しい本人確認ページは、入力をオフにしていても、レシピを作るために記述を送る場合があります。拡張機能のワーカーが再起動しても、入力できたか不明な操作を繰り返すことはありません。再読み込みしたページは新しいページとして扱います。ブラウザーを再起動した後は、このタブで新しくログイン成功を確認するまで、本人確認ページに自動入力しません。**ログイン以外の個人情報フォーム** への入力は未対応です。ログイン中に求められる個人情報は、**ログインページ** の設定に従います。

### AI キー {#ai-key}

**AI キー** に、Claude Console の **Anthropic API キー** を保存できます。この端末がペアリングしている間は、サービスの認証情報の代わりにこのキーで Claude に依頼します。サービスが依頼の中身を作り、拡張機能がそれを自分で Anthropic に送ります。キーはこの端末に残り、Anthropic にだけ送られ、サービスには送られません。**1 日の上限（米ドル）** と **1 か月の上限（米ドル）**（変えなければ 5 ドルと 100 ドル）のどちらかに達すると依頼を止めます。上限額はほかの設定と一緒に同期してすべての端末に適用され、各端末が自分のキーで使った額を数えます。**キーを削除** でキーを消します。

### エクスポートとインポート {#export-and-import}

**エクスポートとインポート** の **ファイルにエクスポート** で、ペアリングした Pateat サービスが保存するものを JSON ファイルに保存します。サイトの設定、保管庫ごとのアイテムとフィールドの制限（保管庫のアカウント名とアイテム名を含みます）、サイトごとに選んだアカウント、この端末が使うレシピです。保管庫の鍵や値、サービスのサインイン情報、AI キーは入りません。別の端末で **ファイルからインポート** を使うと、まずファイルで何が変わるかを表示します。ファイルが、Pateat の使う保管庫のアイテムを決めることになるサイトも表示します。**インポート** を押すとインポートします。自分でエクスポートしたファイルか、信頼できる人から受け取ったファイルだけをインポートしてください。インポートすると、ファイルの設定をその端末の設定に加えます。端末にある設定はすべて残り、同じ項目が両方にあるときはファイルの方を使います。端末にあるレシピは、ファイルの方が新しいときだけ置き換えます。ペアリングした端末では、次の同期でインポートしたレシピをサービスにアップロードします。サービスにすでにあるレシピは除きます。インポートする前に、設定ページを保存するか読み込み直してください。

## Pateat を使う {#using-pateat}

両方の手順が済んだら、保管庫にアイテムのあるサイトのログインページを開きます。**自動** ではそのページのレシピがあれば Pateat がログインし、**入力のみ** ではボタンを自分で押します。レシピがなければ、Pateat はページを値を含めずメールアドレスなどを伏せて記述したものをサービスに送り、Claude でレシピを書きます。それには、この端末の [AI キー](#ai-key)か、[サービスのガイド](https://github.com/risu729/pateat/blob/main/services/api/README.md#claude-credentials)（英語）にあるとおりにサービスで設定した Claude の認証情報が必要です。どちらもなくても、サービスは受け取った記述を保存します。

ツールバーのポップアップには、今のページで Pateat が何をしたかが表示されます（設定ページで **このページ** を隠すと、**アカウントを切り替え** も隠れますが、一時停止は残ります）。複数のアカウントが一致するときにログインするアカウントを選ぶ、サイトの自動ログインを **10 分**、**1 時間**、**再開するまで** 一時停止する、**マスターパスワードを求める** をオンにする、今のホストの **ページでの動作** を設定する、といった操作もできます。カード番号のような個人情報をページが求めたときは、その値を持つ保管庫のアイテムをリンクして **入力** を押します。サービスの **Sites** ページには、レシピ、既定のアカウント、一時停止のあるサイトが、設定プロファイルごとに表示されます。

自動実行の条件で止まっているログインを試すには、ポップアップで対象のページと一致するアカウントを選び、**今すぐログイン** を押します。一時停止中のサイト、自動ログインがオフのプライベートウィンドウ、**許可サイトでだけ自動ログインする** がオンのときの許可サイトでないサイトでも使えます。一致するアカウントが 1 つだけのときや、**このページ** を隠しているときも使えます。今回だけ試し、既定のアカウント、一時停止、次回以降に使うアカウントは変更しません。ポップアップがページの **アカウントを選択** を表示しているときは、そこでログインしてください。**既定のアカウントにする** のチェックでアカウントを記憶できるため、**今すぐログイン** は表示しません。別タブのログインのためにその **ログイン** を押せないとき、ほかのページや埋め込みフォーム、または選択にないアカウントでログインできるとき、押したリクエストがまだ処理中のときだけ、選択の下に表示します。必要に応じて設定済みの AI にページを再判定させるため、通常の上限と料金が適用されます。ポップアップには準備中、レシピ生成中、開始、続行できない状態を区別して表示します。ログインフォームがいつまでも表示されないときなど、準備中の操作は **このログインをキャンセル** で取りやめられます。ログインへのリンクしかないページでは、先に実際のログイン画面を開いてください。別タブで進行中のログイン、サイトへのアクセス権限、保管庫のロック、必要なマスターパスワードの入力などは引き続き確認が必要です。本人確認ページと判定されたページでは、本人確認ページへの入力が **入力のみ** なら、代わりに **入力** を表示します。**オフ** のときは **今すぐログイン** でページを再判定し、このボタンを押しただけでログインとして実行することはありません。

**入力のみ** のままでも、Pateat が待機しているときや入力できる欄を入力し終えたときは、**今すぐログイン** で今回だけボタンも押す通常のログインを実行できます。入力中やパスキーの処理中には切り替えず、サイトやプロファイルの設定も変更しません。**オフ** の確認画面も再判定を頼めますが、再び確認画面と判定された場合は操作しません。

サインインしているサイトでは、ポップアップの **アカウントを切り替え** に一致するアカウントが並びます。**このアカウントに切り替え** を押すと、タブをそのサイトからログアウトしてから、そのアカウントでログインします。初めて切り替えるサイトでは、どの操作でログアウトするかを Pateat サービスに尋ね、見つかったクリックを次の切り替えのために残します。会社や Google のアカウントのような別のアカウントでログインするサイトでは、そのアカウントからもログアウトすることがあります。

サイトのパスキーボタンを押したとき、そのサイトにパスキーのあるアカウントが複数あれば、Pateat はサイトの既定のアカウントでサインインします。ページのフォームか見出しに、そのうち別のアカウントのメールアドレスが 1 つだけ出ているときは、Pateat のパスキー選択ウィンドウをそのアカウントを先頭にして開き、選んだときだけサインインします。そのウィンドウを閉じてからもう一度ボタンを押しても、同じアカウントを先頭にします。Pateat のログインが同じサイトの別のページや、`chatgpt.com` から `auth.openai.com` のようにパスキーを共有するサイトへ移り、ログインが続いているうちに、そのページが読み込み時にパスキーを求めたときは、そのログインのアカウントで応答します。ログインが移った先のページを確かめるのは数秒だけなので、そこで何か入力した後のように、遅れて出た要求はログインのものとして扱いません。サイトが毎回アカウントを選ぶ設定か自動ログインを一時停止しているときは、ログインのアカウントを先頭にしてパスキー選択ウィンドウを開きます。そうでなく、そのページのフォームか見出しに別のアカウントのメールアドレスが出ているときは、そのアカウント、ログインのアカウントの順に並べて開きます。

メールアドレスを入力した後、Pateat のログイン手順がなくパスキーボタンもないページで、入力したアカウントのパスキーを求めるサイトがあります。そのサイトで 1 分以内に、メールアドレス、ユーザー名、電話番号かパスワードを入れたフォームを、ボタンのクリックか Enter で自分で送っていて、そのページかその次のページでサイトが求め、そこで求められたパスキーが保管庫に 1 つだけあり、そのタブで Pateat のログインが動いていなければ、Pateat はそのパスキーの項目でサインインします。パスワードのない項目でもサインインします。1 回フォームを送るごとに応答するのは 1 回だけです。メールアドレス欄のあるフォームなら、ニュースレターや購読のフォームでも数えます。サイトのページが、クリックする場所に自分のボタンを置いて、そのクリックでフォームを送らせることもできます。開いた直後にパスキーを求めるページで、その直前に自分でフォームを送っていなかったとき、ページが自分でフォームを送ったときや、ページ内のフレームが求めたときは、ブラウザーに任せます。サイトが保管庫の複数のパスキーを求めたとき、そのサイトで自動ログインを一時停止しているか毎回選ぶ設定のとき、そのタブで Pateat がすでにそのサイトにサインインしているときも、ブラウザーに任せます。

**自動** では、自分でサイトからログアウトすると Pateat は次のログインページで、自動ログインで使うアカウントでもう一度ログインします。ログアウトしたままにするには、先にそのサイトを一時停止します。10 分のうちに同じサイトへ 2 回ログインしたときは、3 回目はログインせずにアカウントを尋ねます。

プライベート（シークレット）ウィンドウでは、設定ページの **プライベートウィンドウでも自動でログインする** をオンにしない限り、Pateat は自分からログインしません。ポップアップで選んだアカウントではログインします。

## SSO ログイン {#sso-sign-in}

サイトのアカウントには保管庫のログインアイテムを 1 つ使い、ID プロバイダーのアカウントはそれぞれ別のアイテムに保存します。サイトのアイテムには、そのサイト自身のパスワードやパスキーを残せます。SSO の方法ごとに、テキスト型か非表示型のカスタムフィールドを追加します。

| フィールド | 値の例 |
| --- | --- |
| `SSO` | `[Example ID] member@example.test` |
| `SSO 2` | `[Another ID] another-member` |

角括弧の中は、サイトのログインボタンに表示されるプロバイダー名です。その後ろには、ID プロバイダー自身の保存済みアイテムにあるユーザー名を省略せずに書きます。サイトのユーザー名と同じ場合も必要です。括弧内のラベルは、SSO のレシピを作るために、伏せ字処理済みのページの記述と一緒に送ることがあります。ユーザー名は端末に残ります。方法を増やすときは `SSO 3` 以降を使います。フィールドを自動入力から除外すると、その方法は無効になります。

ID プロバイダーが 1 つだけの SSO 専用アカウントでは、URL 形式も使えます。パスワードを空にし、ユーザー名に ID プロバイダーのアカウントのユーザー名を入れ、唯一の `SSO` フィールドに `https://login.example.test` のような ID プロバイダーのオリジンを保存します。1 つのアイテムで URL 形式と括弧の形式を混ぜないでください。これらは書式の例で、実際のサイトで動作を確認したものではありません。

ログイン方法は、サイトのアカウントを選んだ後に選びます。ポップアップの **ログイン方法** で方法を選び、必要なら保存済みの ID プロバイダーのアカウントとログイン先を選びます。ログイン先は、その ID プロバイダーのアイテム自身に保存したウェブサイトから選びます。Pateat はラベルから推測しません。対応付けは設定として同期されるので、ほかの端末でも使われます。ポップアップで変更や削除ができます。サービスの **Vaults** ページではすべての対応付けを一覧でき、どの端末でも接続しなくなった保管庫のアカウントの対応付けなども削除できます。URL 形式の方法でページの入口を 1 つに決められないときは、ページに表示された入口を自分で選びます。

自動で選ぶ順番は、パスキー、番号なしの `SSO`、サイト自身のパスワードです。パスワードを自動で使うのは、番号なしの `SSO` フィールドがないアイテムだけで、番号付きの方法だけのアイテムはパスワードを使います。Pateat が選んだパスキーをサイトが受け付けなかったときは、パスキーを除いて選び直すので、`SSO` の方法を使います。**今すぐログイン** で自分で選んだパスキーを受け付けなかったときは、ログインを止め、ポップアップでパスキーを除いた方法をもう一度選べるようにします。パスワードでのログインに切り替えるのは、SSO の方法がないアイテムだけです。番号付きの SSO は自分で選ぶ別の方法で、選んだ方法は今回のログインにだけ使います。保管庫がロックされたか変更されたとき、SSO フィールドの書式が正しくないときは、選択を止めます。対応付けが決まらないとき、同じ ID プロバイダーのアカウントが重複するとき、ログインに失敗したときは、その SSO の方法を止め、黙ってほかの方法を試しません。アカウント自身のパスキーやパスワードは選べます。

SSO は同じタブで進み、選んだ ID プロバイダーのアカウントだけを使います。そのアカウントは自身のパスワードかパスキーで直接ログインする必要があり、さらに別の SSO へ進むときは止まります。表示されたアカウントと完全に一致する選択肢や、そのアカウントのために認識できる続行の操作には対応しますが、不明なページ、別のアカウント、新しい権限、情報の共有、アカウントの作成では止まります。新しいウィンドウや、ブラウザーが管理する ID の選択ダイアログは扱いません。ID プロバイダーにログインしただけでは成功とせず、元のサイトでログインの完了を確認します。中断した操作を自動でやり直すことはありません。

元のサイトと ID プロバイダーの両方で、ログインページの動作が **自動** で、一時停止していない必要があります。1 つのページだけに使う **今すぐログイン** は、SSO で別のサイトへ進むためにこれらの設定を上書きしません。サイトへのアクセス、保管庫の制限、マスターパスワードの確認は、両方のサイトでそのまま適用されます。**入力のみ** では、SSO の入口や続行のボタンを押しません。Pateat はアカウントを作成せず、ID プロバイダーでの許可や保管庫のアイテムを書き換えません。
