# 初期設定

Pateat の初期設定は、設定ページでの 2 つの手順です。Bitwarden 保管庫に接続し、拡張機能を Pateat サービスとペアリングします。設定ページは、ツールバーのポップアップの **設定を開く** ボタン（スライダーのアイコン）か、`chrome://extensions` の Pateat のカードの **詳細**、**拡張機能のオプション** から開きます。

Pateat の画面は Chrome の言語（英語か日本語）に合わせて表示され、設定ページの **言語** で選ぶこともできます。このページは日本語の表示名で書いています。

## Bitwarden に接続する {#connect-bitwarden}

1. **接続を追加** で **サーバー** を選びます。**Bitwarden クラウド（米国）**、**Bitwarden クラウド（EU）**、または **セルフホスト** です。セルフホストは、自分の Bitwarden サーバーと最新版の Vaultwarden を含みます。セルフホストでは、`https://vault.example.com` のように **サーバーのアドレス** を入力します。HTTPS が必要で、`localhost` と `127.0.0.1` だけは例外です。
2. 接続に `Personal` のような **名前** を付け、Bitwarden の **メールアドレス** と **マスターパスワード** を入力します。
3. **この保管庫を使う** をオンのままにして、**Bitwarden に接続** を押します。
4. Bitwarden が確認を求めると、**手動での確認** のフォームが出ます。**確認方法** を選びます。認証アプリに表示されるコードなら **認証アプリのコード**、サーバーからメールで送ってもらうなら **メールのコード** を選びます（**コードを再送信** でもう一度送ってもらえます）。新しいデバイスでは、Bitwarden が新しいデバイスの確認コードを自動でメールします。設定ページを閉じずに 5 分以内にコードを入力し、**コードを確認** を押します。ほかの 2 段階認証の方式にはまだ対応していません。

Pateat はブラウザーから直接 Bitwarden サーバーにログインし、保管庫を同期して、公式の Bitwarden SDK でこの端末上で復号します。マスターパスワードと確認コードは保存しません。この端末に残るのは次のものです。

- 暗号化された保管庫の写し
- ロック解除の鍵。保管庫のロックを解除している間、その写しを復号します。
- 同期用のログイン情報。あとで保管庫をもう一度同期するのに使います。

接続はそれぞれ 1 行で表示され、主な操作のボタンがあります。ふだんは **同期**、保管庫がロックされているときは **ロック解除**、先にログインが必要なときは **再ログイン** です。**ロック解除** はマスターパスワードを求め、サーバーを使わずにこの端末で確かめます。行のメニューには、ロック解除の鍵を消して同期用のログイン情報を残す **ロック**、両方を消す **ログアウト**、**同期用のログイン情報を削除**、**接続を削除** もあります。**接続を削除** は、もう一度 **接続を削除** を押して確定すると、接続、保管庫の写し、ロック解除の鍵、同期用のログイン情報をこの端末から消します。どれも、ほかの Bitwarden のセッションからはログアウトしません。個人用と仕事用のように、接続はいくつでも追加できます。

### Pateat に使わせるものを選ぶ {#choose-what-pateat-may-use}

接続の行では、Pateat が使えるアイテムも決めます。

- **この保管庫を使う** で、その接続を Pateat に使わせるかどうかを切り替えます。
- **Pateat が使うアイテム** は、**除外設定以外のすべて** か **選択したグループとアイテムのみ** です。
- **除外するアイテムとフィールド** には、Pateat に決して入力させないアイテムと、アイテムのフィールドを並べます。除外は、選択したグループとアイテムより優先します。

除外したカスタムフィールドのあるアイテムが変わり、どのフィールドを除外したのか Pateat が判断できなくなると、このページでフィールドを確認するまで、そのアイテムを使いません。

これらの制限は Pateat にだけ効き、Bitwarden 側は何も変わりません。

## Pateat サービスとペアリングする {#pair-with-a-pateat-service}

1. **同期サービス** で、`https://pateat.example.com` のような **サービスのアドレス** と、サービスのデバイス一覧に表示される **デバイス名** を入力します。
2. **このデバイスをペアリング** を押します。
3. まだサービスにログインしていなければ、Pateat が新しいタブでサービスのログインページを開きます。そこでログインして設定ページに戻ると、Pateat が自動でやり直します。**再試行** と **ログインページを開く** で、それぞれの手順を繰り返せます。
4. サービスにすでに設定があれば、**設定プロファイル** を選びます。既存のプロファイルか、**このデバイスのサイト設定で新しいプロファイルを作成** を選んで **新しいプロファイルの名前** を入力します。プロファイルは、除外したサイト、マスターパスワードを求めるサイト、既定のアカウントを持ち、同じプロファイルのデバイスはそれを共有します。既存のプロファイルを選ぶと、このデバイスのリストはプロファイルのものに置き換わります。このデバイスに除外したサイトか既定のアカウントがあるときは、先に確認します（**置き換えてペアリング**）。マスターパスワードを求めるサイトしかないときは確認しません。

ペアリングに成功すると、**このデバイスをペアリングしました。** と表示されます。その後、Pateat はプロファイルの設定とレシピをサービスから同期し、この端末に写しを持ちます。

サービスはこのデバイスに専用の認証情報を発行します。拡張機能はそれを自身のストレージに保存し、サービスにだけ送ります。90 日使われないと期限が切れます。コンピューターをなくしたときなどは、設定ページの **このデバイスの接続を解除** を押すか、サービスの **Devices** ページで取り消せます。なくしたコンピューターを取り消すと、サービスには接続できなくなりますが、そこにすでにある保管庫の写し、ロック解除の鍵、レシピは消せません。

### Pateat サービス {#the-pateat-service}

サービスは小さな Cloudflare Worker です。ペアリングと管理のページは Cloudflare Access で保護され、拡張機能はデバイスの認証情報で接続します。サービスは、設定プロファイル、どの保管庫のフィールドが各サイトのログインのどこに入るか、レシピを保存し、レシピのないログインページには Claude でレシピを書きます。また、受け取ったページの記述、レシピに従ったログインごとの記録、拡張機能が報告した問題を 1 年間保存します。詳しくは[プライバシーポリシー](./privacy.md#your-pateat-service)にあります。保管庫の値や鍵は受け取りません。サービスのページは **Dashboard**、**Sites**、**Profiles**、**Devices**、**Claude**（Claude の認証情報と使うモデル）、**Problems**（デバイスが報告した警告、エラー、何もしなかった理由）、**Request log** です。サービスのページはまだ英語だけです。

今のところ、サービスはそれぞれ持ち主が自分のために運用しています。`pateat.takuk.me` のサービスは Pateat の開発者のもので、ほかの人は使えません。サービスは運用者が登録した拡張機能 ID からのペアリングだけを受け付けるので、自分で運用するには Pateat の ID か、自分の鍵で署名した自分のビルドの ID を登録します。どちらも[開発ガイド](https://github.com/risu729/pateat/blob/main/docs/development.md#extension-id)（英語）にあります。ペアリングしていない端末でレシピを書けるようにする予定です。

## その他の設定 {#more-settings}

### 保管庫のタイムアウト {#vault-timeout}

**保管庫のタイムアウト** で、保管庫のロックを解除しておく時間を決めます。最後にログイン情報を入力した、パスキーで署名した、ロックを解除した、ログインした時点から数えます。1、5、15、30 分、1、4 時間、**システムのアイドル時**、**システムのロック時**、**ブラウザの再起動時**、**なし**（既定）、**カスタム** の分数から選びます。**タイムアウト時の動作** は **ロック** か **ログアウト** です。この設定はこの端末にだけ保存します。

**なし** では、ロック解除の鍵を Chrome 内の拡張機能のストレージに保存するので、Chrome を再起動しても保管庫は自動でロック解除されます。この鍵は OS のキーストアで保護されていないので、この Chrome のプロファイルを使える人や、そのファイルを読める人は保管庫を使えます。ほかのタイムアウトでは鍵はメモリーにだけあるので、Chrome の再起動や、拡張機能の再読み込みや更新でも保管庫はロックされます。

### マスターパスワードを求めるサイト {#sites-that-ask-for-the-master-password}

Bitwarden のマスターパスワードの再要求は、指定したサイトで守ります。ツールバーのポップアップでそのサイトの **マスターパスワードを求める** をオンにするか、設定ページの **サイト** で **マスターパスワードを求める** から追加します。**サブドメインを含める** でサブドメインも対象になり、**求めない** で外せます。それらのサイトでは、再要求が設定されたログインアイテムとそのパスキーは、Pateat の画面でマスターパスワードを入力してから使います。ほかのサイトでは、ふつうのアイテムと同じように使います。再要求を確かめるのはログインアイテムだけで、リンクしたカードや ID のアイテムの値は、そのアイテムに再要求が設定されていても尋ねずに入力します。最初は何も登録されていません。

### AI キー {#ai-key}

**AI キー** に、Claude Console の **Anthropic API キー** を保存できます。この端末がペアリングしている間は、サービスの認証情報の代わりにこのキーで Claude に依頼します。サービスが依頼の中身を作り、拡張機能がそれを自分で Anthropic に送ります。キーはこの端末に残り、Anthropic にだけ送られ、サービスには送られません。**1 日の上限（米ドル）** と **1 か月の上限（米ドル）**（変えなければ 5 ドルと 100 ドル）のどちらかに達すると依頼を止めます。**キーを削除** でキーを消します。

### エクスポートとインポート {#export-and-import}

**エクスポートとインポート** の **ファイルにエクスポート** で、ペアリングした Pateat サービスが保存するものを JSON ファイルに保存します。サイトの設定、保管庫ごとのアイテムとフィールドの制限（保管庫のアカウント名とアイテム名を含みます）、サイトごとに選んだアカウント、この端末が使うレシピです。保管庫の鍵や値、サービスのサインイン情報、AI キーは入りません。別の端末で **ファイルからインポート** を使うと、まずファイルで何が変わるかを表示します。ファイルが、Pateat の使う保管庫のアイテムを決めることになるサイトも表示します。**インポート** を押すとインポートします。自分でエクスポートしたファイルか、信頼できる人から受け取ったファイルだけをインポートしてください。インポートすると、ファイルの設定をその端末の設定に加えます。端末にある設定はすべて残り、同じ項目が両方にあるときはファイルの方を使います。端末にあるレシピは、ファイルの方が新しいときだけ置き換えます。ペアリングした端末では、次の同期でインポートしたレシピをサービスにアップロードします。サービスにすでにあるレシピは除きます。インポートする前に、設定ページを保存するか読み込み直してください。

## Pateat を使う {#using-pateat}

両方の手順が済んだら、保管庫にアイテムのあるサイトのログインページを開きます。そのページのレシピがあれば、Pateat がログインします。なければ、Pateat はページを値を含めずメールアドレスなどを伏せて記述したものをサービスに送り、Claude でレシピを書きます。それには、この端末の [AI キー](#ai-key)か、[サービスのガイド](https://github.com/risu729/pateat/blob/main/services/api/README.md#claude-credentials)（英語）にあるとおりにサービスで設定した Claude の認証情報が必要です。どちらもなくても、サービスは受け取った記述を保存します。

ツールバーのポップアップには、今のページで Pateat が何をしたかが表示されます。複数のアカウントが一致するときにログインするアカウントを選ぶ、サイトごとに **このサイトで Pateat を使う** をオフにする、**マスターパスワードを求める** をオンにする、といった操作もできます。カード番号のような個人情報をページが求めたときは、その値を持つ保管庫のアイテムをリンクして **入力** を押します。サービスの **Sites** ページには、レシピ、既定のアカウント、除外のあるサイトが、設定プロファイルごとに表示されます。
