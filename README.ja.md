# Pateat

[English](README.md) | 日本語

Auto Login for Chrome（Chrome 向けの自動ログイン）。

ユーザー自身の Bitwarden 保管庫を使い、設定されたログインの流れを最後まで行う Chrome 拡張機能です。**Pateat は当面 Bitwarden にのみ対応します**。ほかの保管庫は今のところ予定していません。パスワード、カスタムフィールド、TOTP、既存のソフトウェアパスキーを扱います。複数の Bitwarden 接続と、サイト・アイテム・フィールド単位の制御は、最初の設計に含まれています。

拡張機能は、バックグラウンドのタブも含めてローカルで動作します。AI はフォームの入力欄の特定と、再利用できるログインレシピの修復を手伝いますが、保管庫の値と署名鍵はローカルにとどまります。基盤には WXT、TypeScript、Valibot を選んでいます。最小限の Cloudflare サービスが設定とレシピを保持し（編集はその Web UI で行います）、推論も提供します。拡張機能はその写しをキャッシュとして持つので、サービスがオフラインの間もログインを続けられます。

最初は保管庫を読み取りだけに使います。後の範囲には、個別に許可する保管庫への書き込み、パスキーでの保管庫プロバイダーへのログイン、外部の OTP やマジックリンク、別途許可するログイン後の操作が含まれます。これらは予定している拡張点であり、最初の実装で約束するものではありません。提供の区切りは[計画](docs/plan.md)で定めています。

名前はラテン語の _pateat_（「開かれてあれ」）に由来します。

**状態：開発中で、未リリースです。** 手動で設定した Bitwarden 接続が保管庫を同期し、公式の OSS SDK でローカルに復号して、暗号化したキャッシュを保持します。ブラウザーを再起動しても自動でロックを解除することもできます（任意）。実際の Bitwarden Cloud US アカウント 1 つで接続を確認しています（V1 鍵、PBKDF2。ほかの KDF、V2 鍵、MFA の方式は未検証です）。HTTPS のサイトでは、拡張機能はサービスにあるログインレシピを実行し、保管庫に一致するアイテムがあるのにレシピのないログインページでは、Claude でレシピを生成するようサービスに依頼します。保管庫に保存したパスキーで署名でき、実際のサイトで動作しています。サービスはオーナー用に `pateat.takuk.me` で動いています。レシピの同期と生成はローカルの Worker に対してのみ検証しており、実際のサイトでのパスワードによるログインはまだ検証していません。未達成の受け入れ条件は[計画](docs/plan.md)にあります。

インストールとチェックの方法は[開発](docs/development.md)を参照してください。本番用の拡張機能は `apps/extension/.output/chrome-mv3/` にビルドされます。これとは別のプローブ用ビルドは、合成テスト専用です。互換性と、人の操作なしでのパスキー対応は、引き続き[受け入れ条件](docs/plan.md)を満たすかどうかによります。

まだ守られていない保護が 2 つあります。Pateat はサイトからのパスキー要求に、ユーザーの存在確認（UP）とユーザー検証（UV）のフラグを立てて応答しますが、自身では存在の確認も検証も行いません（[ADR 0007](docs/adr/0007-existing-passkey-assertions.md#presence-and-verification)）。また、マスターパスワードの再要求が設定された Bitwarden のアイテムも、マスターパスワードを尋ねずに入力に使い、そのパスキーで署名します（[保管庫アダプター](docs/architecture.md#vault-adapter)）。どちらも、Pateat を公開する前に設定項目にする予定です（[計画](docs/plan.md#phase-3-public-release)）。
