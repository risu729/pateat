# Pateat

[English](README.md) | 日本語

Auto Login for Chrome（Chrome 向けの自動ログイン）。

ユーザー自身の Bitwarden 保管庫を使い、設定したログイン手順を最後まで行う Chrome 拡張機能です。**Pateat は当面 Bitwarden にのみ対応します**。ほかの保管庫は今のところ予定していません。パスワード、カスタムフィールド、TOTP、既存のソフトウェアパスキーを扱い、複数の Bitwarden 接続と、サイト・アイテム・フィールド単位の制御に対応しています。

拡張機能は、バックグラウンドのタブも含めてローカルで動作します。AI は再利用できるログインレシピのためにフォームの入力欄を特定し、ログイン済みかどうか分かりにくいページを判定します。レシピの修復は予定段階です。保管庫の値と署名鍵はローカルにとどまります。基盤には WXT、TypeScript、Valibot を選んでいます。最小限の Cloudflare サービスが設定とレシピを保持し（編集はその Web UI で行い、アイテムとフィールドの選択は拡張機能の設定ページに残ります）、Claude を呼び出します。拡張機能はそのコピーをキャッシュとして持つので、サービスがオフラインの間もログインを続けられます。UI は英語と日本語に対応し（[ADR 0043](docs/adr/0043-extension-language-preference.md)）、ツールバーのアイコンには、サイトに一致するアカウントの数と、そのタブでの前回のログインの結果が表示されます（[ADR 0038](docs/adr/0038-login-status-badge.md)）。

当初は保管庫を読み取り専用で使います。後の範囲には、個別に許可する保管庫への書き込み、パスキーでの保管庫プロバイダーへのログイン、外部の OTP やマジックリンク、別途許可するログイン後の操作が含まれます。これらは予定している拡張点であり、最初の実装で約束するものではありません。提供の区切りは[計画](docs/plan.md)で定めています。

名前はラテン語の _pateat_（「開かれてあれ」）に由来します。

**状態：開発中で、未リリースです。** Bitwarden 接続は、操作したときと 5 分ごとに保管庫を同期し、公式の OSS SDK でローカルに復号して、暗号化したキャッシュを保持します。ブラウザーを再起動したときに自動でロックを解除する設定も選べます。実際の Bitwarden Cloud US アカウント 1 つで接続を確認しています（V1 鍵、PBKDF2、新しいデバイスの確認コード）。ほかの KDF、V2 鍵、2 段階認証の方式は、実際のアカウントでは未検証です。CI では、サポートする唯一の版である最新の Vaultwarden に、認証アプリとメールのコードでログインしています（[ADR 0059](docs/adr/0059-latest-vaultwarden-server.md)）。HTTPS のサイトと、`http://` の URI を保存したアイテムでの `http:` のページ（[ADR 0050](docs/adr/0050-http-pages-for-http-items.md)）では、拡張機能はサービスにあるログインレシピを実行し、保管庫に一致するアイテムがあるのにレシピのないログインページでは、Claude でレシピを生成するようサービスに依頼します。保管庫に保存したパスキーで署名できます。サービスはオーナー用に `pateat.takuk.me` で動いており、オーナーの Chrome とペアリングしています。パスワード、カスタムフィールド、TOTP、パスキーによるログインは、生成したレシピでのものも含め、実際のサイトで成功しています。その一覧と未達成の受け入れ条件は[計画](docs/plan.md#phase-1-usable)にあります。

インストールとチェックの方法は[開発](docs/development.md)を参照してください。本番用の拡張機能は `apps/extension/.output/chrome-mv3/` にビルドされます。これとは別のプローブ用ビルドは、合成テスト専用です。互換性と、人の操作なしでのパスキー対応は、引き続き[受け入れ条件](docs/plan.md)を満たすかどうかによります。

まだ守られていない保護が 2 つあります。Pateat はサイトからのパスキー要求に、ユーザーの存在確認（UP）とユーザー検証（UV）のフラグを立てて応答しますが、自身では存在の確認も検証も行いません（[ADR 0007](docs/adr/0007-existing-passkey-assertions.md#presence-and-verification)）。また、マスターパスワードの再要求が設定された Bitwarden のアイテムも、マスターパスワードを尋ねずに入力に使い、そのパスキーで署名します（[保管庫アダプター](docs/architecture.md#vault-adapter)）。どちらも、Pateat を公開する前に設定項目にする予定です（[計画](docs/plan.md#phase-3-public-release)）。
