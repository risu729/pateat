# Automatic login in password managers and agent tools

Researched: 2026-11-08, from vendor pages, vendor documentation and vendor community
forums. Nothing below was tested: no 1Password, LastPass, Bitwarden Enterprise, Skyvern
or Browser Use account was used. It answers the owner's question of 2026-11-08 (02:47
UTC): how Pateat compares with 1Password's universal sign-in and with similar services
and open-source projects. This page owns the comparison with these products, including
1Password for Agents. How agents with their own computers handle logins, and 1Password's
earlier agent products, are in
[browser agents and logins](2026-10-11-browser-agent-logins.md); small open-source
projects inspected as implementation references are in the
[feasibility study](2026-10-10-feasibility.md#similar-projects-references-only). This
page is not a decision and changes no plan item.

## Pateat, for comparison

As of main [`b083bde`](https://github.com/risu729/pateat/commit/b083bde) (see the
[README](../../README.md) and the ADRs linked here):

- The extension fills and submits a login when a login page opens, in background tabs
  too, without a click when one account matches or a default account is saved. When
  several accounts match and none is the default, the person picks one in the popup
  ([ADR 0021](../adr/0021-account-choice-outside-settings.md),
  [ADR 0063](../adr/0063-switch-accounts-from-the-popup.md)). Automatic login can be
  paused ([ADR 0062](../adr/0062-log-in-again-after-a-logout.md)), and CAPTCHAs and some
  extra pages are left to the person ([plan](../plan.md#phase-1-usable)).
- Each site's steps come from a recipe generated by AI for a page with a vault match:
  Cloudflare's Clef model first, and Claude when Clef abstains, normally on the service
  ([ADR 0016](../adr/0016-recipe-generation-trigger.md),
  [ADR 0083](../adr/0083-clef-first-for-sign-in-forms.md)). An AI judge decides whether
  an unclear page after the login is signed in
  ([ADR 0029](../adr/0029-local-sign-in-state.md)).
- It covers passwords, custom fields, TOTP and software passkeys stored in the vault,
  across several pages.
- Sign-in through an identity provider ("Sign in with Google") is an accepted decision
  ([ADR 0026](../adr/0026-sign-in-through-identity-providers.md),
  [ADR 0085](../adr/0085-one-item-for-native-and-sso-login.md)) but is not implemented,
  apart from the account choice and the reserved custom-field names.
- It logs in again after the site logs the person out
  ([ADR 0062](../adr/0062-log-in-again-after-a-logout.md)).
- The vault is the owner's own Bitwarden account or Vaultwarden server.

## 1Password universal sign-in

[Introducing universal sign-in](https://1password.com/blog/introducing-universal-sign-in)
(1Password blog, 2026-09-03) says "Today we're releasing universal sign-in", "available
to all customers in the latest version of the 1Password browser extension" in Chrome,
Edge, Firefox, Safari and other supported browsers. One community thread's title calls
it the "universal sign-on experience".

- On a login page, 1Password "displays a single prompt" listing the person's accounts
  and sign-in methods for the site. The person picks an account, and 1Password "handles
  the rest".
- After that pick, "It submits the forms, enters your one-time code, signs you in with
  your passkey, or selects the right provider for a social login or a managed app", and
  fills "across however many steps it takes". When a step needs the person, "an alert
  will display".
- The blog does not say how 1Password learns a site's steps.
- On 2026-10-01 a 1Password employee called a passkey prompt that could not be dismissed
  while 1Password was locked a bug, and on 2026-10-02 said a fix was being tested in the
  beta
  ([community thread](https://www.1password.community/1password-at-work-58/how-do-i-forward-passkey-requests-to-the-system-in-the-new-universal-sign-on-experience-when-1password-is-locked-25735)).

| | 1Password universal sign-in | Pateat |
| --- | --- | --- |
| Start | The person picks an account in the prompt | Starts by itself when one account matches or a default is saved; otherwise the person picks in the popup |
| Site steps | Not documented | A recipe per site, generated by AI (Clef, then Claude) |
| Methods | Password, one-time code, passkey, social login, managed app | Password, custom fields, TOTP, passkey; identity-provider sign-in is not implemented |
| After a logout | Not documented | Logs in again ([ADR 0062](../adr/0062-log-in-again-after-a-logout.md)) |
| Vault | 1Password | The owner's Bitwarden or Vaultwarden |

## Fill-and-submit settings in password managers

These settings submit a single filled form. None of the pages below says they handle a
second page, a TOTP page or a passkey.

| Product | Setting | Source |
| --- | --- | --- |
| 1Password | "Sign in automatically after autofill" in the extension's Autofill & save settings, with "Don't sign in automatically" per item. In about May or June 2026 (the thread shows only relative times) a user asked why it is on by default, and the moderator TimG said he had filed a feature request to make it opt-in. The current default was not checked | [community thread](https://www.1password.community/discussions/1password/default-for-sign-in-automatically-after-autofill/157816/replies/158148) |
| LastPass | "Automatically Log In", named by a user, not staff, in an undated thread; the original poster could not find it there, so the name is unconfirmed | [community thread](https://community.lastpass.com/discussion/4090/how-can-i-stop-lastpass-from-auto-submitting-credentials-after-auto-filling-the-fields) |
| Bitwarden | No general automatic submit. A reply posted for the Bitwarden team on 2023-09-01 says "automatically submitting a form induces a security risk when the website is compromised"; the forum does not mark the author's role. "Autofill on page load" fills without submitting, is off by default because "compromised or untrusted websites could take advantage of this to steal credentials", and does not fill TOTP codes. The Enterprise policy "Automatic login with SSO" fills and submits when a page is opened from an identity-provider dashboard link carrying `#autosubmit=1` (undated page) | [forum](https://community.bitwarden.com/t/automatically-submit-login-form-on-auto-fill/24?page=3), [help](https://bitwarden.com/help/auto-fill-browser/), [SSO dashboards](https://bitwarden.com/resources/automatic-login-workflow-through-sso-dashboards/) |

## Agent tools

### 1Password for Agents

Announced in
[Introducing 1Password for Agents](https://1password.com/blog/1password-for-ai-agents)
(1Password blog, 2026-10-22); the support page
[Use 1Password to sign in to sites with supported agents](https://support.1password.com/1password-for-agents/)
was published on 2026-11-04.

- The agent asks for a login, and the person approves, picks another item or denies it
  in a prompt that names the requesting app. "After you approve an item, the agent may
  continue to use 1Password to sign in to the website with it for up to 30 days."
- The extension "fills your username, password, and one-time password directly into the
  website's sign-in form outside the agent's view, then submits the form".
- "Passkeys, Login items that rely on sign-in providers, other item types, and shared
  vaults aren't yet supported."
- It needs the 1Password app 8.12.42 or later on the agent's device, and an individual
  or family account on 1Password.com; team, business, 1Password.ca and 1Password.eu
  accounts are not supported.
- The 2026-11-04 support page lists Claude Duet, Grok Bot, Instinct, Muse and Town, each
  with setup steps. The 2026-10-22 blog also listed ChatGPT Work, dots, Browserbase,
  Browser Use, Perplexity and others as coming soon.

Pateat asks for no approval: it logs in on every site that has a recipe and that its
settings allow for the matching vault item. It was seen logging in on a Grok Bot
computer on 2026-10-12
([observation](2026-10-11-browser-agent-logins.md#observed-on-a-grok-bot-computer)).

### Skyvern

[Skyvern's credential documentation](https://www.skyvern.com/docs/credentials/passwords)
describes a browser automation service that reads logins from its own store or from a
connected 1Password, Bitwarden or Azure Key Vault, or a custom credential service.

- "The model that drives the browser gets placeholders, not your values. Skyvern swaps
  in the real value only when it types into the field." A typed value can still appear
  in later screenshots unless Mask Secrets is on.
- One-time codes come from a stored authenticator key, a connected Gmail or Outlook
  inbox, a forwarding relay, or a Skyvern or Twilio phone number. Passkeys need the
  Enterprise plan.
- A signed-in browser can be saved and reused, so later runs skip the login form.

### Browser Use

[Browser Use's `sensitive_data`](https://docs.browser-use.com/customize/sensitive-data)
lets the model see placeholders that the library replaces with the real values, and
replaces a visible password in the model's text input. The page warns that "Vision
models still see the image of the page".

### How these differ from Pateat

Skyvern and Browser Use are a service and a library that the agent's own code calls to
log in, typing the values itself. Pateat is an extension in the person's or the agent's
Chrome that logs in when a login page opens, so the agent does not need to handle the
login form.
